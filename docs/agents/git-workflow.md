# Git 工作流

## 分支策略

- `main` 是稳定的集成基线，不用于日常功能开发。
- 每个独立的 GitHub Issue 或明确独立的开发任务，使用一个专用功能分支完成；不要在同一分支混入无关事项。
- 功能分支从最新的 `origin/main` 创建；若是继续处理同一事项，则继续使用其已有功能分支。
- 分支命名格式为 `feature/<事项号>-<简短英文描述>`，描述使用小写字母和连字符。
- 例如：`feature/20-local-development-bootstrap`。

## 提交与推送

1. 完成一个可验收的开发单元后，先执行与改动相匹配的验证。
2. 将该单元的全部相关改动提交到当前功能分支；提交信息应简洁说明改动，涉及事项时可带上 `#<事项号>`。
3. 验证通过后，立即推送当前功能分支到 GitHub 远程仓库。
4. 不提交本地环境文件、账号密码、API Key、SSH 私钥或其他敏感信息。

功能分支完成并通过验收后，再按仓库协作流程合入 `main`。
