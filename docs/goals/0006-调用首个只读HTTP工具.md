# Goal：Issue #6 调用首个只读 HTTP 工具

> 来源：[GitHub Issue #6](https://github.com/xiaoBaiJLong/ai-mcp-gateway/issues/6)
> 当前状态：阻塞，禁止执行
> Blocked by：#5
> Goal 生成基线：`main@87257483071514516913c4b566eba5aad80cc9a6`

## Goal（目标）

让已授权 Agent 通过统一 `/mcp` 的 `tools/call` 调用一个受控只读 HTTP 工具，完成基础参数映射、用户 `Authorization` 透传、JSON 结果和稳定错误返回。

## Current state（当前状态）

- 生成时没有工具调用、HTTP 客户端、用户凭据透传或错误模型实现，全部验收未完成。
- #5 完成后才可激活；激活时刷新评论、HEAD、协议端点、工具目录实现、可控上游和验证命令。

## Execution order（执行顺序）

1. 验证 #5 完成并记录固定点。
2. 先建立公开管理 API 配置 → `tools/list` → `tools/call` → 可控静态 HTTP 上游的失败端到端测试。
3. 实现每次调用重新授权、基础 path/query 映射和只允许登记上游的请求构造。
4. 实现 `user-passthrough`：默认只透传用户 `Authorization`，不验证用户身份且绝不透传 Agent Key 和 MCP 内部头。
5. 实现 JSON 工具结果、调用 ID及权限、参数、上游和内部错误的稳定分类。

## Completion criteria（完成标准）

- [ ] 已授权 Agent 能调用发布的只读工具并收到受控上游返回的结构化 JSON 结果。
- [ ] `tools/call` 每次重新校验当前 Agent 权限，不能仅依赖先前 `tools/list`。
- [ ] 基础 path 和 query 参数按工具定义映射，未知或非法参数在访问上游前被拒绝。
- [ ] 用户 `Authorization` 被原样透传，网关不验证其中身份。
- [ ] 缺少工具要求的用户凭据时调用被拒绝。
- [ ] Agent API Key、`Host`、连接控制头和 MCP 内部头不会发送到业务上游。
- [ ] 未授权调用、参数错误、业务非 2xx 和网关内部失败可区分，并携带稳定错误码、简化消息和调用 ID。
- [ ] 业务上游失败使用 `isError: true` 工具结果，MCP 格式或协议失败使用协议错误。
- [ ] 端到端测试覆盖成功、透传、缺凭据、未授权、非法参数和上游失败。
- [ ] 敏感值哨兵测试证明响应与日志不泄露 Agent Key、内网地址和敏感上游错误。
- [ ] 相关测试及仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 不实现 Nacos 路由、复杂参数映射、远程 MCP、重试、限流或旧协议兼容。
- HTTP 业务服务认证只允许用户凭据透传，不保存或注入固定服务凭据。
- 只访问管理员登记的静态上游；Agent 参数不能影响目标主机。
- 测试不验证业务服务内部用户权限，只验证网关透传责任边界。
- 默认不 push、不关闭 Issue、不修改 tracker。
