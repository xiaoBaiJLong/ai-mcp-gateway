# Goal：Issue #7 接入 Nacos 并按健康权重路由

## Goal（目标）

让 HTTP 工具按逻辑服务名从 Nacos 动态发现实例，只选择健康且启用的实例并按权重路由，在无可用实例时快速返回稳定错误。

## Current state（当前状态）

- 生成时无 Nacos 订阅、实例模型、权重算法或相关测试，全部验收未完成。
- #6 完成后才可激活；激活时刷新 ticket 评论、HEAD、现有 HTTP 调用接缝、Nacos 依赖和验证命令。

## Execution order（执行顺序）

1. 验证 #6 完成，记录固定点。
2. 用可控 Nacos 与多个假业务实例先定义上线、下线、健康、启用、权重和无实例测试。
3. 实现单个 Nacos 集群/namespace 的服务订阅与逻辑服务绑定，保持服务发现边界小而明确。
4. 实现只对健康且启用实例的加权轮询，并使实例变化无需重新发布工具即可生效。
5. 实现无实例快速失败、调用 ID 和可观测错误，再运行动态与并发验证。

## Completion criteria（完成标准）

- [ ] 工具可按已配置逻辑服务名发现 Nacos 实例，网关不提供第二套实例注册 API。
- [ ] 新增健康且启用的实例无需重新发布工具即可接收新请求。
- [ ] 下线、不健康或禁用实例不会接收新请求。
- [ ] 多实例调用分布在可重复测试样本和明确容差内符合 Nacos 权重方向。
- [ ] 实例健康、启用状态或权重变化能被动态应用。
- [ ] 没有健康且启用实例时立即返回 `SERVICE_UNAVAILABLE`，不会请求最近一次旧实例或静态备用地址。
- [ ] Nacos 健康状态与后续服务熔断状态在模型和观测上保持独立。
- [ ] 集成测试覆盖上线、下线、健康切换、启用切换、权重变化和无实例。
- [ ] 并发测试证明实例快照更新期间不会路由到已移除实例或暴露半更新状态。
- [ ] 相关测试和仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 只支持 Nacos，不实现 Kubernetes Service、其他注册中心、标签路由、一致性哈希、区域优先或灰度路由。
- 只连接一个 Nacos 集群和一个 namespace。
- 不实现生产级多副本和高可用。
- 路由算法保持直接、可测试，不预建通用服务治理框架。
- 默认不 push、不关闭 Issue、不修改 tracker。
