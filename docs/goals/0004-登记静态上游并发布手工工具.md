## Goal（目标）

让管理员登记受控静态 HTTP 上游，手工创建只读工具草稿，完成校验并发布首个不可变工具版本，同时拒绝发布 `destructive` 工具。

## Current state（当前状态）

- 生成时没有上游、工具、版本、发布或测试实现，全部验收未完成。
- 只有 #2 完成后才能激活；激活时重新读取 ticket 评论并记录 HEAD、迁移状态、已有 API 与测试命令。

## Execution order（执行顺序）

1. 验证 #2 完成，记录代码审查固定点。
2. 先为静态上游登记、连通性结果和 SSRF 受控边界建立公开 API 测试。
3. 建立最小工具草稿、风险等级、校验和不可变发布版本模型及迁移。
4. 实现发布规则：缺失配置失败，已发布版本不可原地修改，`destructive` 必须拒绝。
5. 增加 Vue 管理流程并执行数据库、接口和领域状态测试。

## Completion criteria（完成标准）

- [ ] 管理员可登记静态 HTTP 上游，并获得可区分的连通或失败结果。
- [ ] 运行时目标只能引用已登记上游，Agent 输入不能指定任意目标地址。
- [ ] 管理员可手工创建带稳定名称、显示名称和风险等级的只读工具草稿。
- [ ] 合法草稿可以发布，缺少必要配置的草稿不能发布。
- [ ] 每次成功发布形成新的不可变工具版本，任何写接口都不能原地更改已发布版本。
- [ ] 修改已发布定义时创建新草稿，不影响当前发布版本。
- [ ] `destructive` 草稿可以保存和校验，但发布请求被明确拒绝。
- [ ] 集成测试覆盖上游登记、连通失败、草稿校验、发布、不可变版本和新草稿。
- [ ] 失败测试覆盖 `destructive` 发布和未登记目标地址。
- [ ] 相关迁移、后端测试、前端类型检查与构建全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 不实现 Nacos 服务发现、完整 HTTP 参数映射、远程 MCP 或危险工具确认。
- 只允许管理员预登记目标，禁止运行时任意 URL；遵循最小 SSRF 防护边界。
- 发布版本不可变，不能用更新语句直接覆盖线上定义。
- 不引入通用工作流或审批框架。
- 默认不 push、不关闭 Issue、不修改 tracker。
