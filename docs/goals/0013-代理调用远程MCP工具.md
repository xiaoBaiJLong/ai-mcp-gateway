# Goal：Issue #13 代理调用远程 MCP 工具

> 来源：[GitHub Issue #13](https://github.com/xiaoBaiJLong/ai-mcp-gateway/issues/13)
> 当前状态：阻塞，禁止执行
> Blocked by：#6、#12
> Goal 生成基线：`main@87257483071514516913c4b566eba5aad80cc9a6`

## Goal（目标）

让 Agent 从统一 `/mcp` 端点调用经过审核、发布和授权的远程 MCP 工具，并复用本地工具的 RBAC、调用标识、超时、响应限制和错误治理。

## Current state（当前状态）

- 生成时无远程代理调用、上游会话隔离或相关测试，全部验收未完成。
- #6、#12 完成后才可激活；激活时刷新评论、HEAD、本地调用治理、远程目录模型和验证命令。

## Execution order（执行顺序）

1. 验证阻塞任务完成，记录固定点。
2. 建立统一端点 → 可控远程 MCP 的 `tools/list`/`tools/call` 黑盒测试。
3. 实现本地稳定工具标识到远程服务及工具名的确定路由，并隔离不同服务的同名工具。
4. 应用远程服务无认证或固定 Bearer/API Key；明确不透传最终用户凭据。
5. 每次调用重新执行 Agent RBAC，并复用调用 ID、超时、响应限制和稳定错误分类。

## Completion criteria（完成标准）

- [ ] 已授权 Agent 可通过统一 `/mcp` 调用已发布远程工具并收到标准 MCP 结果。
- [ ] 未授权远程工具不可见，直接调用也被拒绝且不泄露工具元数据。
- [ ] 本地稳定工具名可确定路由到正确远程服务和原始工具。
- [ ] 两个远程服务存在同名工具时仍不会串路由或串权限。
- [ ] 上游按配置使用无认证、固定 Bearer 或 API Key。
- [ ] 最终用户凭据不透传给远程 MCP，Agent API Key 和远程固定凭据不相互泄露。
- [ ] 远程认证、协议、业务、超时和响应超限错误可区分并携带调用 ID。
- [ ] 不同远程服务的会话或连接状态相互隔离。
- [ ] 端到端测试覆盖成功、权限、固定凭据、同名工具、超时和远程失败。
- [ ] 敏感值哨兵测试证明响应、日志和审计前置数据不泄漏凭据。
- [ ] 相关测试及仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 不实现远程 MCP 自动故障转移、OAuth、采样、Resources 或 Prompts。
- 不提前实现四版本完整兼容；本 ticket 只完成已登记版本的最小调用路径。
- 复用已有治理，不复制一套远程专用权限或错误系统。
- 远程 MCP 不使用 `user-passthrough`。
- 默认不 push、不关闭 Issue、不修改 tracker。
