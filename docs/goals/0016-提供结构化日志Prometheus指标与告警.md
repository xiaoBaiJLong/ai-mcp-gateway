# Goal：Issue #16 提供结构化日志、Prometheus 指标与告警

> 来源：[GitHub Issue #16](https://github.com/xiaoBaiJLong/ai-mcp-gateway/issues/16)

> Blocked by：#11、#13、#15

## Goal（目标）

提供可通过调用 ID 关联的脱敏结构化日志、低基数 Prometheus 指标和可重复验证的基础告警，覆盖本地/远程调用、治理、配置和依赖状态。

## Current state（当前状态）

- 生成时无运行实现，因此也无目标日志、指标或告警规则，全部验收未完成。
- #11、#13、#15 完成后才可激活；激活时刷新评论、HEAD、现有日志、审计、治理事件和验证命令。

## Execution order（执行顺序）

1. 验证全部阻塞任务完成，记录固定点。
2. 定义一次调用的日志/审计关联测试和敏感值哨兵扫描。
3. 实现统一结构化日志字段和敏感信息过滤。
4. 实现 Prometheus 抓取端点及调用、治理、配置、Nacos、Redis、MySQL 和应用状态指标，控制标签基数。
5. 提供关键失败的基础告警规则，并用可重复故障场景验证规则表达式。

## Completion criteria（完成标准）

- [ ] 每次本地 HTTP 和远程 MCP 调用产生包含调用 ID及必要非敏感上下文的结构化日志。
- [ ] 调用 ID 可以关联运行日志与对应审计记录。
- [ ] Prometheus 指标覆盖调用量、成功/失败、延迟、限流、并发、熔断、无实例和远程 MCP 状态。
- [ ] 指标覆盖配置版本/落后/校验失败、Nacos、Redis、MySQL 连接池和应用实例状态。
- [ ] 指标标签不使用自由用户输入、完整工具参数、凭据或无界实例值，基数测试满足项目设定上限。
- [ ] 基础告警覆盖数据面不可用、配置落后/失败、依赖异常、无健康实例、熔断、错误率/延迟、鉴权失败突增、审计失败和 MySQL 容量/连接池异常。
- [ ] 成功、失败、限流、熔断、无实例和审计写入失败场景能使对应指标按预期变化。
- [ ] 测试故障数据能使关键告警规则进入触发状态，恢复数据能使其退出。
- [ ] API Key、Authorization、Cookie 和固定外部凭据不出现在结构化日志、指标名、标签和值中。
- [ ] 敏感值哨兵扫描日志和指标输出无泄漏。
- [ ] 相关测试及仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 不接入 OpenTelemetry、外部监控平台或长期指标存储。
- 不把高基数业务标识直接作为 Prometheus 标签。
- 告警规则保持基础且可测试，不预建复杂运维平台。
- 结构化日志与审计职责分离，但共享调用 ID 和脱敏原则。
- 默认不 push、不关闭 Issue、不修改 tracker。
