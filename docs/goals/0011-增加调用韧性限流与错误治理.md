## Goal（目标）

在 HTTP 工具调用路径加入总超时预算、幂等重试、按服务熔断、响应大小限制、速率/并发限制和一致错误语义，使上游异常与突发流量保持可控。

## Current state（当前状态）

- 生成时无韧性、限流或治理测试，全部验收未完成。
- #7、#9 完成后才可激活；激活时刷新评论、HEAD、HTTP/Nacos 调用实现、Redis 使用情况和验证命令。

## Execution order（执行顺序）

1. 验证阻塞任务完成，记录固定点。
2. 用可控延迟、失败、大响应和并发上游先定义超时、重试、熔断、限制和错误测试。
3. 实现连接/总超时和跨全部尝试的预算；仅按明确幂等规则重试允许的故障。
4. 实现按业务服务隔离的熔断及探测恢复，并保持 Nacos 健康状态独立。
5. 实现 Agent/工具速率、服务/全局并发和响应大小限制；仅在共享计数确有需要时使用 Redis。

## Completion criteria（完成标准）

- [ ] 默认连接超时 3 秒、工具总超时 30 秒、总超时硬上限 120 秒，且总预算覆盖全部重试。
- [ ] 仅连接失败、502、503、504 可自动重试，默认最多一次。
- [ ] GET 默认可重试；POST/PUT/PATCH/DELETE 只有显式幂等或认可幂等键时才重试。
- [ ] 超时取消上游请求并返回带调用 ID 的 `UPSTREAM_TIMEOUT` 工具错误。
- [ ] 熔断按业务服务隔离，默认 20 次窗口、50% 失败率、30 秒等待，并可按服务配置。
- [ ] 熔断支持打开、有限探测和恢复，不同服务故障不会触发全局熔断。
- [ ] 无健康实例、限流、并发超限和响应过大分别返回稳定错误；超限包含可重试提示和建议等待时间。
- [ ] 响应默认上限 1 MiB、硬上限 10 MiB，超限停止读取并返回 `RESPONSE_TOO_LARGE`。
- [ ] Agent/工具速率及服务/全局并发限制均可配置并使用系统默认值兜底。
- [ ] 集成测试覆盖超时预算、GET 重试、非幂等不重试、熔断打开/探测/恢复、无实例和大响应。
- [ ] 并发测试覆盖 Agent/工具限流、服务/全局并发和需要共享时的 Redis 计数一致性。
- [ ] 相关测试及仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 不引入消息队列、跨地域配额、自适应限流或计费系统。
- 选择成熟且最小的 Spring 生态能力或直接实现，不建立通用治理平台。
- Redis 只用于确有必要的共享限流/并发计数，不承担配置通知。
- 业务失败保持 `isError: true`，协议错误与业务工具错误不得混淆。
- 默认不 push、不关闭 Issue、不修改 tracker。
