# Goal：Issue #5 通过统一 MCP 端点发现授权工具

> 来源：[GitHub Issue #5](https://github.com/xiaoBaiJLong/ai-mcp-gateway/issues/5)
> 当前状态：阻塞，禁止执行
> Blocked by：#3、#4
> Goal 生成基线：`main@87257483071514516913c4b566eba5aad80cc9a6`

## Goal（目标）

让 Agent 使用 API Key 连接统一 `/mcp` 端点，并通过最新 Streamable HTTP 的 `tools/list` 只发现自己获授权的已发布、已启用工具。

## Current state（当前状态）

- 生成时无 MCP、API Key 运行时认证、工具目录或缓存实现，全部验收未完成。
- #3 和 #4 均完成后才可激活；激活时刷新 Issue 评论、HEAD、现有权限/版本模型和测试命令。

## Execution order（执行顺序）

1. 验证 #3、#4 的完成证据，记录固定点。
2. 用最高层黑盒测试先定义最新 Streamable HTTP 初始化和 `tools/list` 行为。
3. 在协议边缘完成 API Key 提取与认证，在领域层复用 Agent→角色→工具集→工具权限结果。
4. 构建只含已发布、已启用、已授权工具的稳定目录，并用最小缓存避免重复计算。
5. 覆盖无权限、错误 Key、重置 Key、停用和稳定排序失败路径。

## Completion criteria（完成标准）

- [ ] 有效 Agent API Key 能在统一 `/mcp` 端点完成最新版本初始化。
- [ ] `tools/list` 只返回该 Agent 获授权且已发布、已启用的工具。
- [ ] 未授权工具的名称、描述和参数结构均不出现在响应中。
- [ ] 对不存在或未授权工具的探测不会泄露两者差异。
- [ ] 无效、缺失或已重置的 API Key 被稳定拒绝。
- [ ] 多角色允许集合并集在工具目录中正确生效。
- [ ] 相同配置下目录顺序和工具描述稳定，缓存不会绕过当前权限。
- [ ] 公开 `/mcp` 端到端测试覆盖初始化、`tools/list`、空权限、停用和无效 Key。
- [ ] 安全测试证明认证失败响应和日志不包含 API Key 明文或未授权工具元数据。
- [ ] 相关协议、权限集成测试和仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。

## Constraints（限制）

- 本 ticket 不实现 `tools/call`、三个旧协议版本或列表变更通知。
- 最新协议的核心行为不能依赖旧版会话模型。
- 工具调用权限仍需在后续 `tools/call` 再校验，不能把列表过滤设计成唯一授权点。
- 缓存采用满足当前单实例需求的最小方案，不提前设计分布式目录系统。
- 默认不 push、不关闭 Issue、不修改 tracker。
