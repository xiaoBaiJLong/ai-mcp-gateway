# Goal：Issue #17 完成端到端验收与性能基线

> 来源：[GitHub Issue #17](https://github.com/xiaoBaiJLong/ai-mcp-gateway/issues/17)
> 当前状态：阻塞，禁止执行
> Blocked by：#8、#10、#11、#14、#15、#16
> Goal 生成基线：`main@87257483071514516913c4b566eba5aad80cc9a6`

## Goal（目标）

从干净环境通过公开管理 REST API 和统一 `/mcp` 端点完成父规格 12 项黑盒验收，并形成可重复的持续 100 QPS 性能基线与通向 500 QPS 的实测差距报告。

## Current state（当前状态）

- 生成时无业务实现、端到端夹具或性能工具，全部验收未完成。
- #8、#10、#11、#14、#15、#16 全部完成后才可激活；激活时刷新父规格和 ticket 评论、HEAD、完整系统行为、所有测试命令和已知失败。
- 来源只写明“持续/稳定时长的 100 QPS”，尚未给出数值时长；如果 #17 解锁时仍未在规格或 ticket 评论中补充该数值，本 Goal 仍不可执行，必须报告这项完成证据缺口而不能自行猜测。

## Execution order（执行顺序）

1. 验证全部阻塞任务及其完成证据，并确认来源已经给出 100 QPS 的数值持续时长；条件齐备后记录最终验收固定点。
2. 从干净环境启动前端、后端、MySQL、Redis、Nacos、可控 HTTP 和远程 MCP 上游。
3. 只通过公开管理 REST API 准备服务、OpenAPI、草稿、发布、Agent、角色和工具集配置。
4. 通过四版本 `/mcp` 客户端执行父规格 12 项功能验收，核对上游行为、运行配置、审计、日志和指标。
5. 执行持续 100 QPS 性能测试，记录环境、吞吐、P95、错误率、资源使用和瓶颈，形成 500 QPS 差距报告。

## Completion criteria（完成标准）

- [ ] 完整验收套件可从干净环境重复启动，不通过内部数据库写入绕过公开管理 API 准备核心配置。
- [ ] 可从 Nacos 服务获取 OpenAPI 文档、选择 operation 并生成草稿。
- [ ] 发布与授权后，授权 Agent 能发现工具，未授权 Agent 看不到且不能调用。
- [ ] Agent 携带 API Key 和用户凭据可完成 HTTP 映射、健康权重路由和结果转换。
- [ ] 固定/隐藏参数、用户凭据、受保护 Header 和上游地址不能被 Agent 参数篡改。
- [ ] 权限或工具目录变化在五秒内影响新发现和新调用。
- [ ] 超时、幂等重试、熔断、限流、响应上限和无健康实例错误符合规格。
- [ ] 远程 MCP 服务可登记、手工同步、差异审核、发布、授权和调用，且不会自动扩权。
- [ ] 四个目标 Streamable HTTP 版本通过下游和远程上游兼容测试，legacy HTTP+SSE 被拒绝。
- [ ] `destructive` 工具可以保留草稿，但不能发布或调用。
- [ ] 审计、结构化日志、Prometheus 指标和告警可以通过同一调用 ID 定位完整调用且不泄漏敏感值。
- [ ] 前端、后端、MySQL、Redis 和 Nacos 可按中文文档本地端到端运行。
- [ ] 持续 100 QPS 测试在规格或 ticket 评论明确的数值时长内完成，并报告吞吐、错误率、`tools/call` 附加 P95、缓存 `tools/list` P95 和资源使用。
- [ ] 不含上游耗时时，报告明确是否达到 `tools/call` 附加 P95 ≤ 50 ms 和缓存 `tools/list` P95 ≤ 200 ms。
- [ ] 性能报告明确测试环境、数据规模、测量方法、原始结果摘要、瓶颈和达到持续 500 QPS 前的实测验证清单，不虚假承诺已达到 500 QPS。
- [ ] 功能端到端套件、相关安全测试、性能脚本校验和仓库完整门禁全部通过；任何跳过项都有书面原因与残余风险。
- [ ] 已以激活时 HEAD 为固定点完成全量代码审查，无未解决规格偏差或高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，提交后工作区干净。

## Constraints（限制）

- 不把本 ticket 变成补做前序功能的容器；发现前序缺口时回到对应 Issue 修复并重新验证依赖。
- 不访问真实业务系统或数据，全部验收使用可控 Nacos、HTTP 和远程 MCP 夹具。
- 本期目标是证明持续 100 QPS并测量通往 500 QPS 的差距，不承诺直接达到 500 QPS。
- 不实现 Kubernetes、多副本、高可用、HPA、备份恢复或容量采购。
- 默认不 push、不关闭 Issue、不修改 tracker。
