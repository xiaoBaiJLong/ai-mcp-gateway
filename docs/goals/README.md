# 目标模式执行说明

本目录把 GitHub 父规格 [#1 企业内部 MCP 网关 MVP](https://github.com/xiaoBaiJLong/ai-mcp-gateway/issues/1) 及其 16 个子 ticket 编译为可验证的执行 Goal。

这些 Goal 是执行契约，不是完成证据。生成时仓库只有需求与架构文档，尚无业务代码、构建脚本或自动化测试；生成基线为 `main@87257483071514516913c4b566eba5aad80cc9a6`。

## 如何使用

### 持续执行整个项目

启动一个支持上下文续期的持久目标循环，并使用[总目标](mcp-gateway-mvp.md)。循环每次只能选择一个当前未阻塞的 ticket，加载对应子目标，在独立的新实现会话中完成、验证和提交，然后重新读取 GitHub 阻塞关系并选择下一个目标。

### 只执行一个 ticket

只有满足以下条件时才能启动对应子目标：

1. Ticket 仍为 `OPEN` 且带有 `ready-for-agent`。
2. Ticket 的所有 `Blocked by` Issue 已经关闭或有可验证的完成证据。
3. 已重新读取 ticket 正文和全部评论。
4. 已记录执行开始时的分支、HEAD、工作区状态、现有行为和实际验证命令。
5. 当前工作区不存在会被本任务覆盖的无关修改。

然后在目标模式中使用对应文件，例如：

```text
使用 docs/goals/0002-跑通本地系统与双角色假登录.md 开启目标模式并执行，严格遵守其中的完成标准和限制。
```

## 统一执行规则

- 每个 ticket 使用一个新实现会话；总目标循环负责跨会话续期，不把 16 个 ticket 塞进同一上下文。
- 默认串行执行。即使同时出现多个前沿，也只有在独立工作树、合并顺序明确且不会争用同一基础代码时才允许并行。
- ticket 解锁后必须刷新其 Goal 中的“当前状态”；本文档记录的 `8725748` 只表示 Goal 生成基线，不能替代执行时固定点。
- 开发中运行最小适用验证；涉及权限、安全、协议、数据一致性或并发时，完成前必须运行相关集成测试和仓库完整门禁。
- 代码审查必须以执行开始时记录的 HEAD 为固定点，同时检查实现标准与 ticket 规格符合性。
- 已授权在全部完成标准通过后创建本地提交。默认不得推送、创建或合并 PR、关闭 Issue、修改标签或修改其他 tracker 状态，除非启动目标时再次明确授权。
- 不修改无关的脏文件或未跟踪文件，不提前实现下游 ticket，不用内部类调用代替公开 REST API 与 `/mcp` 的行为验证。
