# Goal：Issue #10 完成工具版本生命周期与运行时热更新

> Blocked by：#5、#9
> Goal 生成基线：`main@87257483071514516913c4b566eba5aad80cc9a6`

## Goal（目标）

完成工具草稿、校验、发布、回滚、停用和归档生命周期，并使运行时通过本地原子切换与 MySQL 五秒轮询补偿及时加载完整有效快照。

## Current state（当前状态）

- 生成时无生命周期、配置快照、热更新或并发验证实现，全部验收未完成。
- #5、#9 完成后才可激活；激活时刷新评论、HEAD、版本模型、工具目录缓存和验证命令。

## Execution order（执行顺序）

1. 验证阻塞任务完成，记录固定点。
2. 先定义合法/非法状态转换、不可变版本、回滚、停用和归档测试。
3. 实现发布事务生成带版本号的不可变完整快照，并在事务成功后原子切换本实例运行时。
4. 实现每五秒查询 MySQL 版本号的幂等补偿；新快照校验失败时保留最近有效版本。
5. 实现目录缓存失效和适用版本的 `notifications/tools/list_changed`，覆盖并发读取与权限变更。

## Completion criteria（完成标准）

- [ ] 工具状态只允许草稿、校验通过、已发布、已停用、已归档之间定义的合法转换。
- [ ] 每次发布产生新的不可变版本和完整配置快照，线上版本不能原地覆盖。
- [ ] 修改已发布工具创建新草稿；回滚形成可审计的新生效版本并恢复历史行为。
- [ ] 停用后工具不再出现在 `tools/list`，新的 `tools/call` 被拒绝，已开始调用不被强制取消。
- [ ] 归档保留历史版本和相关记录，不作为物理删除。
- [ ] 管理写事务成功后，本实例运行时只观察到完整旧快照或完整新快照。
- [ ] 绕过本实例写入路径的有效数据库版本变化在五秒内被加载。
- [ ] 新快照校验失败时继续使用最近有效版本，并产生可观测失败；同版本重复检查幂等。
- [ ] 目录变化时适用客户端收到 `notifications/tools/list_changed`，主动重新获取也能得到最新目录和权限。
- [ ] 测试覆盖全部状态转换、版本不可变、发布、回滚、停用、归档和 destructive 禁止发布。
- [ ] 并发测试证明切换期间无半更新配置，五秒补偿和失败回退可重复验证。
- [ ] 相关测试及仓库门禁全部通过。
- [ ] 已以激活时 HEAD 为固定点完成代码审查，无未解决高严重度问题。
- [ ] 全部标准通过后创建聚焦本 ticket 的本地提交，工作区干净。
