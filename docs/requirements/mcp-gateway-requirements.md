# MCP 网关系统需求

本文档持续记录需求访谈中已经确认的系统需求。未确认内容不得作为实现依据。

## 文档状态

- 状态：已确认
- 最后更新：2026-08-24
- 交付标准：企业内部生产可用 MVP

## 实现原则

- 一切实现以满足本文档已经确认的需求为目标，选择能够正确完成需求的最简单方案。
- 不为尚未出现的场景预先设计复杂抽象、通用扩展框架或额外中间件。
- 简单不等于把不同职责混在一起；后端管理模块、MCP 运行时模块和前端仍需保持清晰边界。
- 优先使用直接、可读且容易测试的实现，避免过深继承、隐式魔法、无必要的设计模式和过度封装。
- 类、函数和模块保持职责聚焦，使用能够表达业务含义的准确命名。
- 在协议兼容、业务约束、安全边界和非直观取舍处补充适量中文注释，重点解释原因，不重复代码表面行为。
- 核心权限计算、协议适配、参数映射、配置发布和请求路由必须有自动化测试。
- 只有出现真实需求并确认取舍后，才通过 ADR 引入新的架构复杂度。

## 已确认的产品目标

- 建设一个企业私有部署的 MCP 网关。
- Agent 只连接一个统一的 MCP 网关地址，不直接对接各业务服务或远程 MCP 服务。
- MCP 网关将普通 HTTP API 转换为 MCP 工具，同时代理已有的远程 MCP 服务。
- MCP 网关统一实施工具发现、权限控制、调用校验、审计和上游路由。

## 部署与空间边界

- 第一阶段采用单租户模式。
- 第一阶段不划分多个工作空间。
- 所有 Agent 在同一个管理空间中管理。
- 第一阶段不包含公网多租户 SaaS 能力。

## Agent 与工具发现

- 对 Agent 暴露一个统一 MCP 地址。
- 每个 Agent 只能通过 `tools/list` 看到明确授权给它的工具。
- Agent 不应看到未授权工具的名称、描述或参数结构。
- 工具调用时必须再次校验权限，不能只依赖工具列表过滤。
- 聚合目录中的工具名称采用 `<服务标识>.<工具标识>`，例如 `crm.get_user`。
- 工具名称是稳定的全局标识；管理界面可以另外提供中文显示名称。

## Agent 身份与工具授权

- 第一阶段为每个 Agent 分配独立 API Key，并通过 API Key 识别 Agent。
- 第一阶段每个 Agent 同时只使用一个 API Key，不要求多 Key 无中断轮换。
- API Key 使用高强度随机值生成，创建或重置后只展示一次。
- 数据库只保存 API Key 的不可逆摘要，日志只允许记录可识别 Agent 的 Key 前缀。
- API Key 不自动过期；重置后旧 Key 立即失效。
- 第一阶段采用基于角色的工具授权模型。
- 工具组成可复用的工具集，角色关联一个或多个工具集，Agent 被赋予角色。
- Agent 的可见和可调用工具由其角色关联的工具集决定。
- 一个 Agent 可以拥有多个角色，各角色的允许权限取并集。
- 角色之间不支持继承，第一阶段不支持显式拒绝规则。
- 未明确授权的工具默认不可见且不可调用。
- 工具集支持按服务或标签批量选择工具，但保存后必须固化为明确的工具成员列表。
- 后续新增的工具不得仅因符合原有筛选条件而自动获得已有工具集的授权。

## 最终用户上下文

- Agent 身份必须提供，最终用户身份为可选上下文。
- 最终用户身份不参与第一阶段的工具目录授权计算。
- 网关不验证最终用户身份，只将 Agent 提供的最终用户凭据原样传递给业务服务。
- 最终用户身份的真实性和对象级业务数据权限由业务服务负责校验。
- 因网关不验证最终用户身份，网关不能独立判断调用参数或返回结果是否符合该用户的业务权限。
- 网关仍需记录可用的最终用户上下文，但该记录不代表身份已经可信验证。
- 网关负责 Agent 到工具的授权、参数结构和通用安全校验。
- 业务服务负责验证被透传的最终用户凭据，并执行对象级业务数据权限校验。
- Prompt Injection 防护不能只依赖返回结果校验；网关不能替代业务服务的最终用户授权。

## 工具来源

- 支持将业务服务的 HTTP API 配置化转换为 MCP 工具。
- 支持代理已有的远程 MCP 服务，并将其工具纳入统一治理。
- 第一阶段不开发数据库、搜索、文件系统等专用内置连接器。

## HTTP API 配置来源

- 支持导入 OpenAPI 3.x 文档并生成工具定义。
- 支持从指定业务服务的 Swagger/OpenAPI 地址主动获取 OpenAPI 文档。
- 支持不依赖 OpenAPI 文档手工创建工具定义。
- 支持修改自动生成的工具名称、描述、参数映射、认证信息和响应转换规则。
- 工具定义需要版本化、校验并发布后才对 Agent 生效。

## OpenAPI operation 选择

- 导入 OpenAPI 文档后展示全部 operation，由平台管理员选择需要转换的接口。
- 支持按 OpenAPI 标签批量选择 operation。
- 只有被选中的 operation 才生成工具草稿。
- 导入和选择 operation 均不得自动发布工具。

## HTTP 请求转换范围

- 第一阶段支持 `GET`、`POST`、`PUT`、`PATCH`、`DELETE`。
- 支持 path、query、header、cookie 和 body 参数位置。
- 请求体支持 `application/json` 和 `application/x-www-form-urlencoded`。
- 第一阶段不支持文件上传、文件下载和 `multipart/form-data`。
- 第一阶段不支持 WebSocket、原始 TCP 和 gRPC 到 MCP 的转换。

## HTTP 上游范围

- 支持通过 Nacos 逻辑服务名调用业务服务。
- 支持平台管理员预先登记的静态 HTTP 上游。
- 工具不能在运行时把 Agent 参数作为任意目标地址使用。
- 静态上游地址必须在控制面登记并审核，以降低 SSRF 风险。

## 工具参数映射

- MCP 参数可以映射到 HTTP path、query、header、cookie 或 JSON body。
- 支持修改对 Agent 暴露的参数名称和描述。
- 支持必填、默认值、固定值和隐藏参数。
- 支持把多个 MCP 参数组装为嵌套 JSON 请求体。
- 未在 `inputSchema` 中声明的 Agent 参数必须被拒绝。
- Agent 不能控制隐藏参数、固定参数、上游地址和受保护 Header。

## HTTP 上游认证

- 第一阶段只支持 `user-passthrough` 认证模式。
- 最终用户请求进入 Agent 前已经由外部鉴权服务完成认证。
- Agent 将用户凭据传给 MCP 网关，MCP 网关不验证凭据，只原样传递给业务服务。
- 业务服务必须自行验证用户凭据并执行对象级业务权限校验。
- 工具要求用户凭据但请求未携带时，网关必须拒绝调用。
- 第一阶段不由网关保存或注入业务服务固定 API Key、Basic Auth、Bearer Token 等服务凭据。

## HTTP 响应转换

- 默认支持返回结构化 JSON 工具结果。
- 支持使用 JSONPath 从上游响应中提取字段。
- 支持通过受限模板把上游 JSON 转换为适合模型阅读的文本和结构化结果。
- 模板只能访问上游响应和明确允许的调用上下文，不得执行任意代码。

## 调用校验

- 调用前严格按照工具 `inputSchema` 校验参数。
- 拒绝未知字段、错误类型、缺失必填值和超过限制的数据。
- 参数完成 HTTP 映射后，再次校验最终请求。
- 配置 `outputSchema` 时必须校验上游响应。
- 输出校验失败时，不得把不符合约定的结果返回给 Agent。
- 允许管理员收紧 OpenAPI 中不完整或过于宽松的 Schema。

## 错误模型

- JSON-RPC 或 MCP 格式错误、未知工具和网关内部协议处理失败使用 MCP 协议错误。
- 业务服务非 2xx、调用超时或业务失败返回工具结果，并设置 `isError: true`。
- 返回给 Agent 的错误包含稳定错误码、简化消息和调用 ID。
- 不向 Agent 暴露堆栈、内网地址、敏感响应头或上游原始敏感错误。
- 原始错误详情只允许平台管理员和审计查看者查看。

## 用户凭据透传

- 每个业务服务配置允许透传的 Header 和 Cookie 白名单。
- 默认只允许透传 `Authorization` Header。
- 只有确实依赖其他认证 Header 或 Cookie 的业务服务才允许显式增加白名单。
- 无论服务如何配置，都不得向上游透传 Agent API Key、`Host`、连接控制头和 MCP 协议内部头。

## HTTP 调用超时

- 默认连接超时为 3 秒。
- 普通工具默认总超时为 30 秒。
- 业务服务可以设置默认超时，工具可以覆盖服务默认值。
- 第一阶段工具总超时最大为 120 秒。
- 超时后取消上游请求并返回 `UPSTREAM_TIMEOUT`。
- 超时预算覆盖重试在内的全部调用尝试。

## HTTP 自动重试

- 只对连接失败、`502`、`503` 和 `504` 进行自动重试。
- 默认最多重试 1 次。
- `GET` 默认视为可安全重试。
- `POST`、`PUT`、`PATCH` 和 `DELETE` 默认不重试。
- 非 `GET` 请求只有被明确标记为幂等，或使用业务认可的幂等键时才允许重试。
- 重试不得突破工具总超时预算。

## 熔断

- 熔断状态按业务服务统计。
- 连续失败或窗口失败率超过阈值时打开熔断器，熔断期间调用快速失败。
- 恢复等待期结束后允许少量探测请求，成功后逐步恢复。
- 默认采用 20 次调用窗口、50% 失败率阈值和 30 秒熔断时间。
- 熔断阈值允许按业务服务配置。
- Nacos 实例健康状态与网关服务熔断状态分别维护和观测。

## 无可用实例

- Nacos 中没有健康且启用的服务实例时，立即返回 `SERVICE_UNAVAILABLE`。
- 不调用最近一次健康但当前已不健康的实例。
- 第一阶段不自动回退到静态备用地址。

## 响应大小限制

- 上游响应体默认最大为 1 MiB。
- 每个工具可以在允许范围内下调或上调限制。
- 第一阶段响应体硬上限为 10 MiB。
- 响应超限时停止读取并返回 `RESPONSE_TOO_LARGE`。
- 审计记录响应大小和摘要，不记录被截断的完整内容。

## 限流与并发

- 支持按 Agent 限制调用速率。
- 支持按工具限制调用速率。
- 支持按业务服务限制最大并发数。
- 支持网关全局并发上限。
- 未单独配置时使用系统默认值。
- 超限返回可重试错误和建议等待时间。
- 第一阶段使用内存或 Redis 实现令牌桶与并发计数，不包含计费和复杂配额。

## 工具风险等级

- 每个工具必须标记 `read`、`write` 或 `destructive` 风险等级。
- `read` 表示只读查询，`write` 表示创建或修改业务数据，`destructive` 表示删除、转账、发布等高风险操作。
- OpenAPI 导入时根据 HTTP 方法给出初始风险建议，但最终由平台管理员确认。
- 风险等级用于默认授权、用户确认要求和审计策略，不能直接等同于 HTTP 方法。

## 高风险调用确认

- 第一阶段不实现高风险调用确认凭据。
- `destructive` 工具可以创建和校验草稿，但禁止发布和调用。
- `write` 工具依赖 Agent 角色授权、严格参数校验、用户凭据透传和业务服务权限校验。
- 后续只有接入可信的用户确认签发方后，才能开放 `destructive` 工具发布。

## 调用审计

- 每次调用固定记录调用 ID、时间和 MCP 协议版本。
- 记录 Agent、可选最终用户标识、工具名称、工具版本和风险等级。
- 记录权限判断与高风险确认判断结果。
- 记录目标业务服务、服务实例、配置快照版本和数据面实例。
- 记录调用结果、错误码、耗时、重试次数以及请求和响应大小。
- 控制面的登录、配置修改、导入、发布、回滚、停用和权限变更必须记录操作者及前后差异。

## 审计正文与脱敏

- 默认不保存完整工具参数和返回正文。
- 允许按工具开启脱敏后的参数和结果审计。
- 允许短期保存调用失败的原始错误详情。
- 脱敏规则至少支持按 JSONPath、Header 名和字段名匹配。
- Token、API Key、Cookie 和明确标记的敏感字段不得写入普通日志或审计正文。

## 审计保留期限

- 工具调用元数据默认保留 180 天。
- 脱敏后的参数和结果默认保留 30 天。
- 原始错误详情默认保留 7 天。
- 控制面操作记录和发布历史长期保留，除非平台管理员配置归档策略。
- 所有保留期限允许配置。

## 外部服务凭据存储

- 远程 MCP 服务和受保护 OpenAPI 文档的获取凭据以明文保存在 MySQL 中。
- 管理 API 和控制台不得在初次保存后再次返回完整凭据。
- 日志、审计和配置导出不得包含完整凭据。
- 该方案接受数据库读取权限泄漏会直接暴露外部服务凭据的风险，以换取第一阶段实现简单。

## 可观测性

- 输出结构化日志，并提供 Prometheus 指标。
- 第一阶段不接入 OpenTelemetry 链路追踪。
- Prometheus 指标至少覆盖调用量、成功率、错误率、延迟、限流、并发、熔断、配置版本、Nacos 状态、MySQL 连接池和数据面实例状态。
- 第一阶段支持数据面不可用、配置落后或校验失败、Nacos/Redis 异常、无健康实例、服务熔断、错误率或延迟超限、鉴权失败突增、审计写入失败以及 MySQL 容量或连接池异常告警。

## 容量与性能目标

- 设计容量为 500 个 Agent、5,000 个已发布工具和持续 500 QPS。
- 第一阶段先完成持续 100 QPS 压测，再逐步优化到设计容量。
- 不包含上游业务服务耗时时，`tools/call` 网关附加延迟 P95 不超过 50 ms。
- 已缓存的 `tools/list` P95 不超过 200 ms。
- API Key、RBAC 和 Schema 校验耗时包含在网关附加延迟内。
- 配置发布到全部数据面实例不超过 5 秒。

## 技术栈

- 后端使用 Java 21、Spring Boot 3.x 和 Spring Cloud Alibaba/Nacos Client。
- 持久化使用 MySQL，分布式限流和必要缓存使用 Redis。
- Web 管理控制台使用 Vue 3 和 TypeScript。

## 数据库迁移

- 使用 Flyway 管理 MySQL Schema 版本。
- 第一阶段不实现数据库备份、恢复、配置导出和专用迁移工具。

## 本地运行与 Kubernetes

- 第一阶段优先确保前端、后端、MySQL、Redis 和 Nacos 可以在本地直接运行并完成端到端开发。
- 容器镜像、Helm Chart、Kubernetes Deployment、Service、ConfigMap、健康探针、HPA、优雅停机和滚动升级属于后续部署阶段。
- 后续 Kubernetes 交付不负责安装 MySQL、Redis 和 Nacos。

## 长耗时调用

- 第一阶段不实现 MCP Tasks 扩展。
- 同步工具调用必须在 120 秒内结束。
- 更长的业务操作由业务服务创建业务任务并返回任务 ID。
- 业务服务另行提供查询工具，Agent 使用任务 ID 查询进度和结果。

## MCP 协议范围

- 不支持 legacy HTTP+SSE MCP 传输协议。
- 以 MCP `2026-07-28` Streamable HTTP 为主要协议版本。
- 兼容旧版 Streamable HTTP 客户端。
- 明确兼容 `2025-03-26`、`2025-06-18` 和 `2025-11-25` 三个旧版 Streamable HTTP 协议版本。
- 不支持 legacy HTTP+SSE，但允许 Streamable HTTP 在统一 MCP 端点按协议需要使用 `text/event-stream` 响应。
- 新旧协议差异由网关边缘的协议兼容层处理，不应让旧版会话模型成为核心领域模型。

## 部署与服务发现

- 整个系统部署在 Kubernetes 中。
- 业务服务使用 Spring Cloud Alibaba 生态进行服务治理。
- 第一阶段只集成 Nacos 服务注册与发现。
- 业务服务实例动态注册到 Nacos，MCP 网关通过 Nacos 获取实例变化。
- 第一阶段连接一个 Nacos 集群和一个 namespace。
- 业务服务直接向 Nacos 注册，MCP 网关只订阅实例，不提供第二套业务服务实例注册 API。
- Nacos 是业务服务实例状态的权威来源。
- 第一阶段不实现 Kubernetes Service、Eureka 等其他服务发现适配器。

## 系统部署形态

- 第一阶段采用前后端分离，Web 控制台作为独立 Vue 应用。
- 控制面和数据面合并在一个 Spring Boot 后端应用中，不作为两个独立服务部署。
- 后端内部仍按管理模块和运行时模块隔离职责。
- 管理模块负责工具定义、服务配置、Agent、角色、工具集和发布管理。
- 运行时模块负责 MCP 协议处理、身份与权限校验、工具调用校验、实例路由和结果返回。
- 第一阶段只运行一个后端实例，不承诺多副本、高可用和控制面故障隔离。

## 配置发布与生效

- 控制面把已发布配置生成带版本号的不可变配置快照。
- 数据面订阅配置更新，完成完整性和合法性校验后原子切换到新版本。
- 数据面保留最近一个有效配置版本，不能因新快照校验失败而丢失现有运行配置。
- 角色或工具集权限发布后，应在 5 秒内影响所有新调用。
- 正在执行的工具调用不因权限变化而取消。
- `tools/list` 使用最新有效权限，`tools/call` 在每次调用时重新校验当前权限。
- 对旧版客户端发送 `notifications/tools/list_changed`；新版协议的工具列表缓存必须及时失效或使用足够短的 TTL。
- 后端启动时从 MySQL 加载最新有效快照。
- 发布事务完成后，运行时模块立即校验并原子切换到新快照；同时每 5 秒查询 MySQL 版本号进行补偿检查。
- 同一版本的重复检查必须幂等，新快照失败时继续使用旧版本并告警。

## 工具定义生命周期

- 工具定义状态依次为：草稿、校验通过、已发布、已停用、已归档。
- 每次发布生成一个不可变工具版本。
- 修改已发布工具时生成新草稿，不直接覆盖线上版本。
- 支持回滚到任意历史发布版本。
- 停用工具后，它不再出现在 `tools/list` 中，新的 `tools/call` 必须被拒绝。
- 工具停用不强制中止已经开始执行的调用。
- 归档不删除历史版本和审计记录。

## 控制面操作角色

- 第一阶段只有平台管理员和审计查看者两种控制面角色。
- 平台管理员拥有最高权限，负责系统配置、服务维护、Agent、权限和发布管理。
- 审计查看者只能查看配置、历史记录、调用日志和告警，不得执行修改操作。
- 第一阶段不设置独立的服务维护者角色，也不实现自定义控制面 RBAC。
- 第一阶段使用假登录验证角色边界，只提供 `admin/666666` 和 `auditor/666666` 两个固定账号。
- `admin` 映射平台管理员，`auditor` 映射审计查看者。
- 假登录仅用于本地第一阶段，不得视为生产认证方案。

## 业务服务请求路由

- 只选择 Nacos 标记为健康且启用的服务实例。
- 按照 Nacos 实例权重执行加权轮询。
- 第一阶段不实现标签路由、一致性哈希、区域优先和灰度路由。

## 远程 MCP 服务接入

- 远程 MCP 服务由平台管理员在控制面登记。
- 登记内容至少包括服务地址、传输协议版本和上游认证凭据。
- 控制面连接远程 MCP 服务并获取工具列表，生成待审核的工具定义。
- 远程 MCP 工具只有审核并发布后才可以进入 Agent 的工具目录。
- 不允许远程 MCP 服务新增工具后自动扩大现有 Agent 权限。
- 第一阶段只支持管理员手工触发远程工具目录同步，不执行周期检查。
- 手工同步发现变化时生成差异和新草稿，不自动发布。
- 上游兼容 `2026-07-28`、`2025-03-26`、`2025-06-18` 和 `2025-11-25` Streamable HTTP。
- 上游不支持 legacy HTTP+SSE。
- 上游认证支持无认证和平台管理员配置的固定 Bearer Token 或 API Key。
- 远程 MCP 调用不透传最终用户凭据。

## OpenAPI 文档获取

- 支持根据 Nacos 服务和约定路径自动探测 OpenAPI 文档。
- 支持管理员为服务指定完整的 OpenAPI 文档 URL 和获取凭据。
- 支持管理员手工刷新和可选的定时检查。
- 文档发生变化时展示差异并生成新工具草稿，不自动发布。

## 管理接口

- 第一阶段同时提供 Web 管理控制台和 REST 管理 API。
- Web 管理控制台必须调用与外部自动化相同的 REST 管理 API，不建立独立后端逻辑。
- 控制台至少覆盖服务、工具、OpenAPI 导入、Agent、角色、工具集、发布历史和调用审计。

## 基础设施约束

- 尽量减少中间件数量。
- 使用 MySQL 持久化控制面数据、历史版本和不可变配置快照。
- Redis 只用于分布式限流、并发计数或确有必要的运行时缓存，不用于配置版本通知。
- 第一阶段不为配置发布额外引入 Kafka、RocketMQ 等消息系统。

## MCP 能力范围

- 第一阶段只实现工具发现和调用，即 `tools/list` 与 `tools/call`。
- 第一阶段不实现 Resources、Prompts、MCP Apps。
- 第一阶段不实现 MCP Tasks 扩展。

## 第一阶段验收标准

1. 可以从 Nacos 服务获取 OpenAPI 文档，选择 operation 并生成工具草稿。
2. 工具发布后，授权 Agent 能通过 `tools/list` 发现工具，未授权 Agent 看不到该工具。
3. Agent 携带 API Key 和用户凭据后，可以完成 HTTP 工具调用、参数转换和健康实例路由。
4. 固定参数、用户认证信息和受保护 Header 不能被模型通过工具参数篡改。
5. 角色或工具集权限发布后，在 5 秒内对运行时生效。
6. 超时、幂等重试、熔断、限流和无健康实例错误符合本文档约定。
7. 可以登记、手工同步、审核、发布和调用远程 MCP 工具。
8. `2026-07-28`、`2025-03-26`、`2025-06-18` 和 `2025-11-25` Streamable HTTP 客户端通过兼容测试。
9. `destructive` 工具不能在第一阶段发布或调用。
10. 审计、结构化日志、Prometheus 指标和告警能够定位一次完整调用。
11. 前端、后端、MySQL、Redis 和 Nacos 可以在本地完成端到端运行。
12. 持续 100 QPS 压测通过，并形成向持续 500 QPS 设计目标优化的结果报告。

## 明确延期的范围

- 公网多租户 SaaS、多租户和多工作空间。
- Resources、Prompts、MCP Apps 和 MCP Tasks 扩展。
- legacy HTTP+SSE、文件上传下载、`multipart/form-data`、WebSocket、原始 TCP 和 gRPC 转换。
- `destructive` 工具的可信用户确认与正式开放。
- 数据库备份恢复、配置导出和专用迁移工具。
- Kubernetes 交付、多副本、高可用、HPA 和滚动升级。
- 远程 MCP 工具目录的自动周期同步。
